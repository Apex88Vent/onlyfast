# OnlyFast code audit

**November 4, 2026 · main · d4c07efa644c · Audit only**

## A. Executive summary

1. **Prioritize data isolation and authorization.** The offline save queue is shared by all accounts on a browser or WebView and replay replaces the original owner with the currently signed-in account. The checked-in share policies also let a caller with SELECT access enumerate public share records without submitting a code. Those records can include the sharer's email. The first issue follows directly from the application code. The second is confirmed for the supplied policy and grants, with production exposure still unverified.
2. **Enforce limits where the data changes.** Setup Assist trusts a caller-chosen weekend key. Assist and timing OCR both check quotas before the provider call and record usage afterward through a separate read and upsert. Rookie setup count and 48-hour restrictions live in UI flows. The repository's setup policies check ownership, class and feature access, but lack equivalent time and count checks. Decide which restrictions are intended as server guarantees before altering behavior.
3. **Optimize the images and the initial route independently.** The isolated web output is **53,050,838 bytes**, including **51,676,861 bytes of public files**. The initial JavaScript is **1,211,393 bytes minified / 329,833 bytes gzip**, with Vite's large chunk warning. Published size is dominated by artwork. Startup JavaScript is dominated by eager feature imports and the shared app shell and SDKs. The historical copies and package cache primarily affect repository and build input size.
4. **Establish a stable release baseline.** App and Vite config typechecks passed. The later test run was **487/488**. The remaining failure is in the preserved custom iOS billing bridge suite. Scoped lint reported **415 errors and 97 warnings**. The later isolated production build and the exported release environment and module checks passed for the local configuration. Device behavior, hosted schemas and store configuration require separate evidence.
5. **Preserve release boundaries.** The stock Median paywall is the selected native billing path. The later working copy has a house-only web advertising controller. Median wrapper configuration and existing installed binaries have independent behavior. Treat advertising and purchase activation as separate release decisions.
